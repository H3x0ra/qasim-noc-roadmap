A repeatable study loop

Make every session produce proof.

The goal is not to finish lessons quickly. It is to be able to repeat the work, explain the decisions, and show what you built.

01

Follow the next stop

Use the dashboard’s “Next up” card, then open that week’s plan and keep the order unless you need the built-in catch-up rule.

02

Rebuild without notes

After the lesson and lab, repeat the core task from a clean state. Write down where you got stuck and what fixed it.

03

Save evidence in Git

Commit one useful artifact each week: a script, diagram, test collection, runbook, dashboard, or short incident report.

Weekly rhythm

Three sessions of 60–90 minutes. A fourth is optional.

1. Learn and lab

75 min. Minimum theory, then the KodeKloud lab.

2. Rebuild

75 min. Redo it from scratch, no lesson. Where you stall is what you still don't know.

3. Apply and write

90 min. Do the week's task, write the artifact, commit it.

4. Catch-up (optional)

45 min. Review or absorb a missed session.

Missed days cost nothing. Resume at the next session, never restart. Two weeks behind: drop Kubernetes II first, then trim Kubernetes I. Weeks 1–12 are never cut.

Capstone: Ops-Status

One environment that uses every skill. Terraform builds it, Docker runs it, scripts and Prometheus watch it, and you break it on purpose and write the RCA.

Deploy flow

terraform apply, then docker compose up -d, cron starts the checks, Newman smoke test confirms.

Alerts

Host down, disk over 85%, API 5xx rate, container restarting, EC2 status check.

Break it, then write the RCA

Disk fills from logs. Bad env var crash-loop. Security group blocks 443. DNS or route fault. Volume permission error. Revoked S3 credentials.

Make the work reviewable

Turn labs into a professional portfolio.

Reuse the deliverables already in the 16-week route. These finishing touches make your work easier for a teammate or interviewer to understand.

01

A clear project README

Explain the problem, architecture, prerequisites, run steps, expected result, and cleanup command. Add a short table of contents when it grows.

02

Runbooks that guide action

For each failure, capture symptoms, checks in order, expected healthy output, recovery steps, and how to confirm service is restored.

03

Incident stories with evidence

Record impact, a timestamped timeline, root cause, mitigation, and prevention. Tie each conclusion to a log, metric, or test.

04

Safe, repeatable demos

Use sample data and sanitized screenshots. Include a cost note, budget guardrail, and teardown steps for cloud resources.

Optional polish after the core route

Small additions that strengthen the same work without expanding the 16-week plan:

Record a 2-minute capstone walkthroughAdd one automated API smoke checkInclude a simple cost estimateWrite an incident handoff summaryShow a clean teardown and rebuild
